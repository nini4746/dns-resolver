# DNS 리졸버 명세

> 학습용 토이 4번. 언어 C, 라이브러리 금지, 1~2주 분량, 1인 개발.
> 이 문서는 spec-goal-flow 자문자답 인터뷰(3라운드, 최종 모호성 0.16)와 엣지 프로브, 셀프 그릴링 1패스를 거쳐 확정되었다.

## 한 줄 목표

루트 네임서버부터 직접 반복 질의하는 반복형(iterative) DNS 리졸버 `./resolve`를 C로 만든다. `dig +short`와 같은 답을 내고, 루트부터 내려간 위임 경로를 출력한다.

## 학습 목표 (왜)

- 네트워크 바이너리 프로토콜 파싱: RFC 1035 와이어 포맷을 바이트 단위로 직접 조립/해석
- 압축 포인터(RFC 1035 §4.1.4): 오프셋 점프하는 바이너리 포맷의 안전한 파싱
- 반복 질의: 위임 계층(. → com. → example.com.)을 따라가는 해석 알고리즘
- TTL 기반 캐싱

## 범위 내

- UDP 소켓으로 DNS 쿼리 패킷 직접 조립과 응답 파싱 (resolver 라이브러리 금지)
- 루트 힌트(하드코딩 IP)부터 시작하는 반복 질의
- 레코드 타입: A, AAAA, NS, CNAME (CNAME 체이싱 포함)
- 글루 없는 위임 처리 (NS 이름을 별도 반복 해석)
- TTL 기반 인메모리 캐시 (프로세스 수명 내)
- CLI: `./resolve [-t A|AAAA|NS] [-v] <domain> [<domain>...]`
- 위임 경로 출력, NXDOMAIN/NODATA/타임아웃/truncation 에러 구분

## 범위 외

- EDNS0: 512바이트 제한 완화가 목적인데 학습 핵심(파싱, 반복 질의)과 무관. 확장 후보.
- TCP 폴백: TC=1 응답은 에러 처리로 충분. 확장 후보 (미니 Redis 전에 붙여볼 만함).
- DNSSEC: 검증 로직이 프로젝트 하나 분량. 학습 목표 아님.
- PTR, MX, TXT 등 기타 레코드 타입: 파싱 구조가 같아 학습 가치 중복.
- 캐시 포이즈닝 방어(소스 포트 랜덤화, 0x20 인코딩): 보안 토이가 아님. 단 트랜잭션 ID 검증은 범위 내.
- /etc/hosts, resolv.conf 참조: 시스템 리졸버 경로를 일부러 우회하는 프로젝트이므로 모순.
- 멀티스레드, 데몬화, 영속 캐시: 1~2주 분량 초과. 영속 캐시는 미니 Redis(토이 5번) 연계 확장 후보.
- IPv6 트랜스포트(네임서버에 IPv6로 질의): AAAA 레코드 파싱은 하되 질의 자체는 IPv4 UDP로만.

## 요구사항

### R1. DNS 질의 메시지 직렬화

- 검증 문장: 임의의 유효한 도메인 이름과 질의 타입(A/AAAA/NS)에 대해 RFC 1035 §4 와이어 포맷 질의 패킷을 조립할 수 있다.
- 현재 상태: 코드 없음.
- 목표 상태: 헤더(12바이트) + QNAME(레이블 길이 프리픽스 인코딩) + QTYPE + QCLASS를 버퍼에 쓰는 함수. 랜덤 트랜잭션 ID, RD=0(반복 질의이므로 재귀 요청 안 함).
- 수용 기준:
  - [ ] `example.com` A 질의 패킷의 바이트가 기대값과 일치한다 (단위 테스트, 하드코딩 바이트 비교)
  - [ ] 레이블 63바이트 초과 또는 전체 이름 255바이트 초과 입력을 에러로 거부한다
  - [ ] 트랜잭션 ID가 매 질의마다 달라진다

### R2. DNS 응답 메시지 파싱

- 검증 문장: 실제 네임서버 응답 패킷에서 헤더 플래그, answer/authority/additional 섹션의 A/AAAA/NS/CNAME 레코드를 추출하고, 손상된 패킷에서 크래시나 무한 루프 없이 에러를 반환한다.
- 현재 상태: 코드 없음.
- 목표 상태: 압축 포인터를 따라가며 이름을 디코딩하고, 각 섹션의 레코드(이름, 타입, TTL, RDATA)를 구조체 배열로 반환하는 파서. 모르는 타입은 RDLENGTH만큼 건너뛴다.
- 수용 기준:
  - [ ] 압축 포인터가 포함된 실제 응답 패킷(캡처해서 하드코딩)에서 이름이 올바르게 디코딩된다
  - [ ] 자기 자신 또는 뒤쪽 오프셋을 가리키는 포인터 루프 패킷에서 유한 시간 내 에러를 반환한다 (앞 방향 오프셋만 허용 + 점프 상한 128)
  - [ ] RDATA나 이름이 패킷 경계를 넘는 조작 패킷에서 에러를 반환한다 (모든 읽기에 경계 검사)
  - [ ] 잘린 패킷(중간에서 끊김)을 fuzz성 반복 절단 테스트해도 크래시가 없다

### R3. UDP 질의와 신뢰성

- 검증 문장: 지정한 네임서버 IP에 UDP로 질의를 보내고, 타임아웃/재시도/폴백을 거쳐 검증된 응답을 받거나 명확한 에러로 끝난다.
- 현재 상태: 코드 없음.
- 목표 상태: sendto/recvfrom 기반 질의 함수. 응답 대기 타임아웃 3초, 서버당 재시도 1회, 실패 시 호출자가 다음 서버로 폴백할 수 있는 인터페이스.
- 수용 기준:
  - [ ] 8.8.8.8에 단발 질의를 보내 파싱된 응답을 받는다 (통합 테스트)
  - [ ] 트랜잭션 ID가 다른 응답은 폐기하고 타임아웃까지 계속 대기한다
  - [ ] 무응답 IP(예: 192.0.2.1)에 질의하면 3초 x 2회 이내에 타임아웃 에러를 반환하고 프로세스가 블록되지 않는다

### R4. 루트부터 반복 해석

- 검증 문장: 하드코딩된 루트 힌트에서 시작해 위임을 따라가며 도메인의 A/AAAA/NS 레코드를 해석하고, 각 단계를 경로로 기록한다.
- 현재 상태: 코드 없음.
- 목표 상태: 루트 → TLD → 권위 서버 순으로 referral(answer 비고 authority에 NS)을 추적. additional 섹션의 글루 A 레코드로 다음 서버 IP를 얻고, 글루가 없으면 NS 이름을 별도 반복 해석한다. 재귀 깊이 상한 8. 한 존의 NS가 전부 실패하면 에러.
- 수용 기준:
  - [ ] `./resolve example.com`이 루트부터 최소 2단계 위임(. → com. → 권위 서버)을 거쳐 A 레코드를 출력한다
  - [ ] 글루 없는 위임을 가진 도메인이 해석된다 (NS 이름 별도 해석 경로가 verbose 로그에 보임)
  - [ ] RCODE 3 응답 시 "NXDOMAIN"을, NOERROR + answer 0개 시 "NODATA"를 출력하고 비0 종료한다
  - [ ] TC=1 응답 시 부분 답을 사용하지 않고 truncation 에러로 비0 종료한다
  - [ ] 존재하지 않는 TLD(예: `foo.invalidtld12345`) 질의가 유한 시간 내 에러로 끝난다

### R5. CNAME 체이싱

- 검증 문장: 답이 CNAME이면 타깃 이름으로 해석을 이어가 최종 A/AAAA에 도달하고, 루프나 과도한 체인은 에러로 끝난다.
- 현재 상태: 코드 없음.
- 목표 상태: answer 섹션에 CNAME과 타깃의 A가 함께 오면 추가 질의 없이 사용, CNAME만 오면 타깃으로 새 반복 해석. 체인 깊이 상한 8. 경로 출력에 CNAME 단계 표시.
- 수용 기준:
  - [ ] CNAME을 가진 실제 도메인(예: `www.github.com`)이 최종 IP까지 해석되고 경로에 CNAME 단계가 보인다
  - [ ] 체인 깊이 9 이상(또는 루프)을 시뮬레이션하면 "CNAME chain too long" 에러로 비0 종료한다

### R6. TTL 기반 캐시

- 검증 문장: 해석 과정에서 얻은 레코드가 TTL 동안 인메모리 캐시에 저장되고, 캐시 히트 시 네트워크 질의가 생략된다.
- 현재 상태: 코드 없음.
- 목표 상태: (이름, 타입) 키로 레코드와 만료 시각을 저장하는 캐시. 위임 과정에서 얻은 NS와 글루 A도 캐시. 만료 엔트리는 조회 시 무시.
- 수용 기준:
  - [ ] 같은 실행에서 `./resolve -v a.example.com b.example.com` 시 두 번째 도메인 해석에서 루트와 TLD 질의가 생략됨이 verbose 로그로 확인된다
  - [ ] 같은 도메인을 두 번 넘기면 두 번째는 네트워크 질의 0회로 캐시에서 답한다
  - [ ] TTL 0 레코드는 캐시되지 않거나 즉시 만료 처리된다 (단위 테스트: 만료 시각 조작)

### R7. CLI와 경로 출력, dig 일치

- 검증 문장: `./resolve [-t A|AAAA|NS] [-v] <domain>...`이 dig와 같은 답을 내고, 위임 단계마다 한 줄씩 경로를 출력한다.
- 현재 상태: 코드 없음.
- 목표 상태: 기본 타입 A. 경로 출력 형식은 단계마다 "어느 서버에 무엇을 물었고 무엇을 받았는가"가 드러나는 한 줄 (예: `@198.41.0.4 (.) example.com A -> referral com.`). 마지막에 최종 레코드 목록 출력. 성공 시 종료 코드 0.
- 수용 기준:
  - [ ] 고정 테스트 도메인 목록(example.com, www.iana.org, 기타 안정 도메인 3개 이상)에서 `./resolve <d>`의 IP 집합이 `dig +short <d>`의 IP 집합과 순서 무관 일치한다 (비교 스크립트 제공, TTL은 비교 제외)
  - [ ] `-t AAAA`, `-t NS` 결과가 각각 `dig +short <d> AAAA`, `dig +short <d> NS`와 집합 일치한다
  - [ ] 경로 출력에 루트, TLD, 권위 서버 단계가 각각 최소 한 줄씩 나타난다
  - [ ] 인자 없음 또는 잘못된 `-t` 값이면 usage를 출력하고 비0 종료한다

## 부정 수용 기준 (must-NOT)

- [ ] `getaddrinfo`, `gethostbyname`, `res_query` 등 시스템 리졸버 호출이 소스 어디에도 없다 (부트스트랩 포함, `grep`으로 검사 가능)
- [ ] TTL이 만료된 캐시 엔트리를 답으로 반환하지 않는다
- [ ] 트랜잭션 ID가 일치하지 않는 응답을 수용하지 않는다
- [ ] TC=1 응답의 부분 답을 최종 답으로 출력하지 않는다
- [ ] 어떤 입력 패킷에도 패킷 버퍼 밖을 읽지 않는다

## 제약

- 언어 C (C99 이상), 외부 라이브러리 금지. 소켓/시간 등 POSIX 표준 API만 허용.
- 단일 스레드, 단일 프로세스.
- 질의 트랜스포트는 IPv4 UDP만. 응답 버퍼 512바이트 (EDNS0 없음).
- 타임아웃 3초, 서버당 재시도 1회, 존당 NS 폴백.
- 상한: 압축 포인터 점프 128, CNAME 체인 8, 글루 없는 NS 해석 재귀 깊이 8.
- 루트 힌트는 소스에 하드코딩 (a~m.root-servers.net 중 4개 이상의 IPv4 주소).

## 엣지 프로브 해소 기록

| 엣지 | 처리 | 반영 위치 |
|---|---|---|
| 압축 포인터 루프 공격 | 명세 추가 | R2 |
| CNAME 체인 루프 | 명세 추가 | R5 |
| 512바이트 초과 TC=1 | 명세 추가 (에러 처리, TCP 폴백은 범위 외) | R4, must-NOT |
| 무응답 네임서버 | 명세 추가 | R3 |
| 글루 없는 위임 | 명세 추가 | R4 |
| NXDOMAIN vs NODATA | 명세 추가 | R4 |
| 트랜잭션 ID 불일치 | 명세 추가 | R3, must-NOT |
| 레이블/이름 길이 초과 | 명세 추가 | R1, R2 |
| 패킷 경계 초과 읽기 | 명세 추가 | R2, must-NOT |
| dig 라운드로빈 불일치 | 테스트로 방어 (고정 도메인 목록) | R7 |
| 루트 힌트 IP 변경 | 기각 (수십 년 단위로 안정적, 토이에 갱신 메커니즘은 과잉) | - |

## 완료 판정

R1~R7의 모든 수용 기준 체크박스와 must-NOT 전부가 pass면 완료. 최종 데모: `./resolve example.com`이 dig와 같은 답 + 루트부터 내려간 경로 출력.

## 확장 후보 (이번 범위 아님)

- EDNS0 (OPT 의사 레코드로 UDP 페이로드 확대)
- TCP 폴백 (TC=1 시 같은 질의를 TCP로 재시도)
- 미니 Redis(토이 5번)를 캐시 백엔드로 연결
