# Plan 01: DNS 메시지 조립과 파싱

## 목표

네트워크 없이 순수 바이트 조작만으로 DNS 질의 패킷을 조립(R1)하고 응답 패킷을 파싱(R2)한다. 이 프로젝트의 학습 핵심(바이너리 와이어 포맷, 압축 포인터)이 여기 다 있다.

## 컨텍스트

- 프로젝트: /Users/yunho/project/dns-resolver (현재 README.md뿐, 코드 없음)
- 명세: .planning/SPEC.md 의 R1, R2
- 참조: RFC 1035 §4.1 (메시지 포맷), §4.1.4 (압축 포인터), §3.1 (이름 인코딩)
- 이 plan은 네트워크를 쓰지 않는다. 테스트 패킷은 `dig` 실행 중 tcpdump나 `dig +noedns` 결과를 바이트로 캡처해 하드코딩한다. 캡처 방법 힌트: `sudo tcpdump -X -i any udp port 53` 또는 파이썬 scapy로 한 번 덤프.

## 작업

1. `src/dns_message.h` - 자료구조 설계: 헤더 필드 구조체, 리소스 레코드 구조체(이름, 타입, 클래스, TTL, RDATA), 파싱 결과(섹션별 레코드 배열). 타입 상수 A=1, NS=2, CNAME=5, AAAA=28.
2. `src/dns_encode.c` - 질의 조립:
   - 12바이트 헤더 쓰기 (ID, 플래그 RD=0, QDCOUNT=1). 네트워크 바이트 오더 주의 (htons).
   - 이름 인코딩: `example.com` → `\x07example\x03com\x00`. 레이블 63바이트, 전체 255바이트 제한 검사.
   - QTYPE, QCLASS(IN=1) 붙이기.
3. `src/dns_decode.c` - 응답 파싱:
   - 헤더 읽기 (ID, QR, RCODE, TC, 각 섹션 카운트).
   - 이름 디코딩: 압축 포인터(상위 2비트가 11이면 14비트 오프셋 점프) 처리. 안전장치 두 개 - 포인터는 반드시 현재 위치보다 앞을 가리켜야 하고, 점프 횟수 상한 128.
   - 모든 읽기 전에 경계 검사 (오프셋 + 읽을 길이 <= 패킷 길이). 헬퍼 함수 하나로 통일하면 실수가 줄어든다.
   - 레코드 파싱: A(4바이트), AAAA(16바이트), NS/CNAME(RDATA가 압축된 이름일 수 있음), 모르는 타입은 RDLENGTH만큼 스킵.
4. `tests/test_message.c` - 단위 테스트 (assert 기반, 프레임워크 불요):
   - 조립: example.com A 질의의 기대 바이트와 memcmp.
   - 파싱: 캡처한 실제 응답 바이트에서 레코드 추출 확인.
   - 악성 패킷: 자기 참조 포인터, 뒤쪽 포인터, RDATA 경계 초과, 레이블 길이 조작.
   - 절단 테스트: 정상 패킷을 길이 0부터 N까지 잘라가며 전부 파싱해도 크래시 없음 확인 (ASan 켜고: `-fsanitize=address`).
5. `Makefile` - `make test`로 위 테스트 실행. CFLAGS에 `-Wall -Wextra -fsanitize=address` 권장.

## must-haves

- 경계 검사 없는 raw 포인터 산술이 파서에 없을 것
- 포인터 루프 방어 (앞 방향 강제 + 점프 상한)
- 이름 길이 제한 검사 (조립과 파싱 양쪽)
