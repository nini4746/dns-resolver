# 0005. TC=1은 최종 답에서만 에러로 처리

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
EDNS0가 없어 응답은 512바이트로 제한되고, 큰 referral은 TC=1로 잘려 온다. 잘린 부분 답을 최종 답으로 출력하면 안 된다. TCP 폴백은 범위 외다.

## 결정
- answer가 있는 응답이 TC=1이면 `RES_TRUNCATED`로 끝낸다.
- answer 없는 referral이 TC=1이면 포함된 NS와 glue를 그대로 사용한다.
- answer도 referral도 없는 TC=1 응답은 `RES_TRUNCATED`로 끝낸다 (`src/resolve.c`).

## 대안
- 모든 TC=1을 에러 처리: 큰 referral을 주는 존을 해석하지 못한다.
- TCP 폴백: 범위 외. 확장 후보로 남긴다.

## 결과
- 장점: 서버는 512바이트에 맞게 레코드 수를 줄이므로 잘린 referral의 레코드는 각각 완전하다. 잘린 답은 절대 출력하지 않는다.
- 단점/감수한 점: 최종 답이 512바이트를 넘는 이름은 해석할 수 없다.
