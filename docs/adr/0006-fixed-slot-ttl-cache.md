# 0006. 고정 슬롯 TTL 캐시와 가장 가까운 존에서 해석 시작

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
여러 도메인을 한 번에 해석하면 루트와 TLD 질의가 반복된다. 만료된 레코드는 절대 답으로 내면 안 되고, 만료 테스트를 실제로 기다리며 돌리기는 어렵다.

## 결정
- 캐시는 고정 `CACHE_CAP` 8192 슬롯을 선형 탐색한다 (`src/cache.c`). 키는 (이름, 타입), 이름은 대소문자 무시.
- 응답의 모든 A/AAAA/NS/CNAME을 저장한다. TTL 0은 저장하지 않고, 가득 차면 가장 먼저 만료될 항목을 축출한다.
- 시각을 주입받는 `cache_put_at`/`cache_get_at` 변형을 둔다.
- 다음 해석은 캐시된 NS와 glue A가 있는 가장 가까운 존에서 시작한다.

## 대안
- 해시 테이블: 단일 프로세스 CLI 규모에서는 단순한 구조로 충분하다.
- 실제 시계만 사용: 만료 테스트에 실제 대기가 필요하다.
- 매번 루트부터: 여러 도메인 해석 시 루트/TLD를 다시 묻는다.

## 결과
- 장점: 두 번째 도메인부터 루트/TLD 질의가 생략된다. `test_cache`, `test_cname`이 네트워크 없이 돈다.
- 단점/감수한 점: 조회가 O(n)이다. 캐시는 프로세스 수명 동안만 유지된다.
