# 0002. 경계 검사와 점프 상한으로 패킷 파싱 종료 보장

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
응답 패킷은 신뢰할 수 없는 입력이다. 압축 포인터(RFC 1035 §4.1.4)는 자기 자신이나 뒤쪽을 가리켜 무한 루프를 만들 수 있다.
RDATA나 이름이 패킷 경계를 넘는 조작 패킷도 막아야 한다.

## 결정
- 압축 포인터는 현재보다 앞쪽 오프셋만 허용하고, 점프 횟수 상한 `DNS_MAX_JUMPS` 128을 둔다.
- 모든 정수 읽기를 `read16`/`read32`와 길이 비교로 처리한다 (`src/dns_decode.c`).
- 파싱 결과는 고정 크기 배열에 담는다. 섹션당 `DNS_MAX_RECORDS` 64, 패킷 `DNS_MAX_PACKET` 512바이트. 동적 할당은 없다.

## 대안
- 방문 오프셋 집합으로 루프 감지: 두 조건만으로 종료가 보장되고 추가 메모리가 필요 없다.
- 포인터 산술 직접 사용: 경계 검사가 흩어져 누락되기 쉽다.
- `malloc` 기반 가변 배열: 512바이트 패킷에 담길 레코드 수가 제한적이라 필요 없고, 메모리 관리 실수가 생길 수 있다.

## 결과
- 장점: 포인터 루프, 경계 초과, 잘린 패킷에서 크래시 없이 에러를 반환한다. 테스트는 AddressSanitizer 빌드로 돈다.
- 단점/감수한 점: 레코드 수 상한을 넘는 응답은 다룰 수 없다. EDNS0가 없어 512바이트를 넘는 응답도 받지 않는다.
