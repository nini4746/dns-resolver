# 0003. IPv4 UDP 전송과 select() 데드라인 기반 타임아웃

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
UDP 응답은 오지 않거나, 다른 트랜잭션 ID로 올 수 있다. 무응답 서버에서 프로세스가 블록되면 안 되고, ID가 다른 응답은 버리되 남은 시간만큼은 계속 기다려야 한다.

## 결정
- 질의는 IPv4 UDP 포트 53으로만 보낸다. AAAA 레코드는 파싱하지만 AAAA glue는 쓰지 않는다.
- `select()`와 시도별 절대 데드라인으로 대기한다. `QUERY_TIMEOUT_SEC` 3초, `QUERY_RETRIES` 1회 (`src/dns_query.h`).
- 트랜잭션 ID는 `rand()`로 만들고, ID가 다른 응답은 폐기한다.
- 한 서버가 실패하면 호출자(`src/resolve.c`)가 목록의 다음 서버로 폴백한다.

## 대안
- `SO_RCVTIMEO`: ID 불일치 응답을 버린 뒤 남은 시간만 기다리는 루프를 짜기 어렵다.
- IPv6 트랜스포트: 범위 외.
- 암호학적 난수 ID: 캐시 포이즈닝 방어는 범위 외. ID 일치 검증만 목적이다.

## 결과
- 장점: 무응답 서버에서도 3초 x 2회 안에 끝난다. 잘못된 ID의 응답을 수용하지 않는다.
- 단점/감수한 점: 소스 포트 랜덤화, 0x20 인코딩 같은 포이즈닝 방어가 없다. IPv6 전용 네임서버에는 질의할 수 없다.
