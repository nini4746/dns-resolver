# 0001. 시스템 리졸버 없이 루트 힌트부터 직접 질의

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
프로젝트 목적은 RFC 1035 와이어 포맷과 반복 질의를 직접 다루는 것이다. OS 리졸버에 맡기면 학습 대상이 사라진다.
시작점인 루트 서버 주소도 어딘가에서 얻어야 한다.

## 결정
- `getaddrinfo`, `gethostbyname`, `res_query` 등 시스템 리졸버 호출을 쓰지 않는다. 서버 주소는 IP 리터럴만 받아 `inet_pton(AF_INET, ...)`으로 변환한다 (`src/dns_query.c`).
- 질의 패킷 조립과 응답 파싱을 직접 구현한다 (`src/dns_encode.c`, `src/dns_decode.c`).
- 루트 힌트는 `src/root_hints.c`에 IPv4 8개(a, b, c, d, f, i, k, m)를 하드코딩한다.

## 대안
- `getaddrinfo`로 부트스트랩: 프로토콜을 직접 다루는 목적과 맞지 않는다. 루트 힌트가 IP라 이름 조회가 필요 없다.
- priming 질의, 힌트 파일 로드: 루트 주소는 수십 년 단위로 안정적이라 갱신 메커니즘이 과하다.

## 결과
- 장점: 리졸버 라이브러리 금지 규칙을 `grep`으로 검사할 수 있다. 외부 의존 없이 POSIX 소켓/시간 API만 쓴다.
- 단점/감수한 점: 루트 서버 주소가 바뀌면 소스를 고쳐야 한다.
